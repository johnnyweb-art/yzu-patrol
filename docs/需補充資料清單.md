# 需補充資料清單

依「是否影響上線」排序。A 類未提供前無法正式上線；B 類影響使用品質；C 類可上線後再補。

## A 類：上線前必須提供

| 編號 | 需要的資料 | 用途 | 建議提供單位 | 格式 |
|------|-----------|------|-------------|------|
| A1 | **大門駐衛警與側門駐衛警各自的巡邏範圍**：據點名稱、位置（大樓／樓層）、屬於大門或側門 | 建立據點、QR 標籤與兩條巡邏路線 | 總務處（已表示會提供） | Excel |
| A2 | 每個據點的檢查項目（例如「門窗上鎖」「滅火器壓力正常」） | 巡邏員現場勾選 | 總務處、保全 | Excel，可依據點類型共用 |
| A3 | 巡邏路線：哪些據點組成一條路線、是否需依序巡邏 | 建立路線 | 保全 | Excel |
| A4 | 巡邏人員名單：工號、姓名、角色（巡邏員／班長／管理者） | 建立帳號 | 保全公司或總務處 | Excel |
| A5 | 巡邏員身分：校聘或外包保全；手機為公發或個人手機 | 決定帳號管理與裝置綁定方式 | 總務處 | 文字說明 |
| A6 | 系統管理者 1–2 位（負責新增人員、核准換機） | 建立第一位管理者 | 總務處 | 姓名、工號 |
| A7 | 緊急聯絡電話：校安中心、保全值班室 | 顯示於 SOS 畫面 | 學務處、保全 | 電話號碼 |
| A8 | 網站放置位置：學校網頁伺服器或外部雲端空間，須為 https | 部署網頁 | 資訊處 | 網址 |
| A9 | 資料庫帳號：學校自行申請 Supabase，或由資訊處提供替代方案 | 存放巡邏資料 | 資訊處、總務處 | 帳號 |

## C 類：上線後可再補

| 編號 | 需要的資料 | 用途 |
|------|-----------|------|
| C1 | 校徽或指定配色 | 介面識別 |
| C2 | 既有紙本巡邏表格 | 比對欄位，確保稽核需要的資訊都有記錄 |
| C3 | 保全契約中的巡邏 KPI（例如完成率門檻） | 後台統計報表依契約指標呈現 |
| C4 | 總務報修系統是否有介接方式 | 異常自動轉報修單 |

## 需要決策的事項

1. **個資同意書**：由總務處或法務確認 `docs/個資告知範本.md` 內容後，請巡邏員簽署。
2. **外包人員資料權屬**：若巡邏員為保全公司派駐，需在契約中約定巡邏資料歸屬學校、保全公司可查閱的範圍。
3. **代巡的處理程序**：主管覆核發現「疑似代巡」時，依保全契約或人事規定如何處置。
