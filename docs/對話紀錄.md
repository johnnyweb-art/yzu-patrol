## 第 1 輪｜初始需求

**提問（原文）**
> 我想設計一項元智大學警衛智學校各據點巡邏的手機app，巡邏員可以打開手機登錄幾月幾號開始巡邏，並在每個巡邏點 掃描QR CODE 後即完成定點巡查任務 並紀錄查詢照片，每一位巡查員只能記錄自己的巡查，避免代巡，如果你有其他在巡查過程需要紀錄的內容 也請一併考慮進入設計

**回覆重點**
1. 核心議題：讓每一筆紀錄能證明「此人、此時、在此地、看見此狀況」。
2. 指出原構想最弱的假設：只用 QR Code 無法防止代巡，QR 可被翻拍。
3. 提出五層防代巡驗證：身分、裝置、位置、時間、照片證據。
4. 建議增列：據點檢查清單、異常事件單、SOS、漏巡原因、交接班紀錄、巡邏軌跡、訪客與可疑人員紀錄。
5. 導入方案：主方案自行開發，替代方案採購既有巡邏系統。

**產出**：初版設計規格書與可操作手機原型（`docs/初版設計規格書.html`）。

## 第 2 輪｜開發方式與時程

**提問（原文）**
> 你說的 主方案：自己開發。 可以接學校的單一登入，資料留在學校 是甚麼概念 你開發這個軟體要這麼久嗎

**回覆重點**
1. 解釋「單一登入」與「資料留在學校」的意義。
2. 修正時程估計：寫程式本身 1–3 天即可，12 週主要是上架、資安審查、據點盤點等學校流程。
3. 建議第一版改做「網頁版 App」（PWA），免上架，用手機瀏覽器加入主畫面即可使用。

## 第 3 輪｜開始開發網頁版

**提問（原文）**
> 我就寫網頁版 你把其他所考慮的點一併考慮進去 若需要我補充其他資料請列清單給我

**產出**
1. 巡邏員手機端：登入、一人一機、開始巡邏、QR 掃描＋GPS 圍欄、App 內即時拍照（浮水印、雜湊值）、檢查清單、異常回報、事件回報、SOS、隨機自拍、結束巡邏與交接、離線暫存。
2. 管理後台：即時看板、巡邏場次（地圖與軌跡）、定點紀錄查詢與覆核、事件管理、身分確認、統計分析、據點與路線管理、QR 標籤列印、人員與裝置。
3. 資料庫結構與權限規則（`supabase/schema.sql`），以 PostgreSQL 實際測試。
4. 示範模式：不需伺服器即可試用。
5. `docs/需補充資料清單.md`、`docs/資料填寫範本.xlsx`、`docs/已知限制.md`、`docs/個資告知範本.md`。

**測試**：資料庫規則與瀏覽器操作流程（38 個步驟）全部通過。

## 第 10 輪｜帳號可否變更、資料存放、自動匯出

**提問（原文）**
> IPHONE手機可以登錄，我想知道日後巡邏員第一次登錄後 可以隨時變更或刪除嗎? 另外每日的巡查資料會記錄在哪? 可以設計每日 自動匯出巡查表給隊長

**回覆重點**
1. 巡邏員可自行變更密碼；手機、姓名、角色由主管或管理者修改；已送出的巡查紀錄不可修改或刪除，作為稽核證據。
2. 示範模式資料存在單一瀏覽器；正式模式存在雲端資料庫，照片存檔案空間。
3. 新增「每日巡查日報表」：後台預覽、下載 Excel（摘要、巡邏場次、異常與事件、定點紀錄明細），並可每天自動寄給隊長。

## 第 11 輪｜寄送時間與 QR Code 替代方案

**提問（原文）**
> 好，相關資料再確認 每天23:59分寄出當天的，我在思考一個問題，是不是一錠需要QR CODE來確認巡查，有其他的方式可以確認 巡查員 進入巡邏點嗎

**回覆重點**
1. 日報表改為每天 23:59 寄出當天（00:00–23:59）紀錄；跨午夜的巡邏每筆紀錄只計入發生當天。
2. 比較 QR Code、GPS 定位打卡、NFC、藍牙信標、門禁刷卡、巡更棒、照片 AI 比對。
3. 指出關鍵：任何「到點確認」證明的是手機到了，不是本人到了；防代巡的關鍵在身分確認。
4. 建議依據點類型混用：戶外 GPS 打卡、室內 QR、門禁點用刷卡紀錄、高風險點日後改 NFC。

## 第 13 輪｜首次註冊與掃臉報到

**提問（原文）**
> 我剛剛測試 應該要有第一次使用的註冊申請，日後每次只要掃臉就可以進入系統報到並開始巡邏 可以這樣設計嗎

**產出**
1. 第一次使用：填寫工號、姓名、手機、所屬單位，同意個資告知，設定 Face ID 或指紋後送出申請。
2. 班長於管理後台核准或退回（附原因）。
3. 日常使用：開啟後掃臉一次，即登入、報到並開始巡邏。
4. 安全補強：臉部辨識改由伺服器驗證簽章；開始巡邏時是否通過身分驗證由伺服器判定，不採信手機回報。

**測試**：註冊、核准、退回、一次掃臉報到、失敗無法進入、他機無法冒用等 17 個步驟全部通過。
